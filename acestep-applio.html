Music and voice · the local half of the build

ACE-Step and Applio

The two apps that turn the morning's lyrics into a finished vocal in his own voice. This is sessions 6 and 7 of the Mac guide opened out into every command, with a checkpoint after each one.

Needs Apple Silicon, 16 GB or better ACE-Step Python 3.11 or 3.12, port 7860 Applio Python 3.10, port 6969 Verified 17 Aug 2026

Three things to know before he types anything

Each one is a night lost if he finds it out the hard way.

They want different versions of Python. ACE-Step needs 3.11 or 3.12. Applio needs 3.10. This sounds like a conflict and is not: each installer builds its own virtual environment and keeps to it, so both versions can sit on the same Mac without arguing. He just has to install both and let each app do its own setup. The way this goes wrong is trying to run one inside the other's environment, which produces dependency errors that look like a corrupted download.

Neither app does the other's job. ACE-Step writes the song and sings it in a voice that is not his. Applio takes that finished vocal and replaces the timbre with his. There is no setting in ACE-Step for "use my voice" and no setting in Applio for "write me a song." The whole build is the handoff between them.

Applio here is for converting, not for training

The .pth and .index he loads in session 8 come from the free Colab GPU in session 5 of the Mac guide. Applio on Apple Silicon converts a vocal in seconds and trains a model almost not at all. Installing it does not change that.

One branch before he starts. On an Intel Mac, or 8 GB of memory, ACE-Step locally is not worth attempting: run the music step in Colab and keep the Mac for Applio, the video, and the upload. Session 0 of the Mac guide has the full table.

Part one: ACE-Step, the music

1

Install uv

2 minutesScreen share

ACE-Step does not use pip or conda. It uses uv, which reads the project's lockfile and builds the whole environment itself. This is good news: it is one command and it does not ask him to understand virtual environments. 

$ curl -LsSf https://astral.sh/uv/install.sh | sh

Then quit Terminal completely with Command+Q and reopen it, the same way Homebrew needed in session 1. The installer adds uv to the path, and the path only takes effect in a new session.

Checkpoint

This prints a version number rather than "command not found":

$ uv --version
uv 0.x.x
2

Clone ACE-Step and build its environment

10 minutes, mostly downloadingScreen share 
$ cd ~
$ git clone https://github.com/ace-step/ACE-Step-1.5.git
$ cd ACE-Step-1.5
$ uv sync

uv sync is the step that takes a while. It resolves every dependency and downloads them into a local environment inside the folder. Nothing outside ~/ACE-Step-1.5 is touched, which also means deleting that folder is a clean uninstall.

Checkpoint

uv run acestep --help prints usage text instead of a traceback. A traceback here almost always means the wrong Python version, so check python3 --version reads 3.11 or 3.12.

3

First launch, and the long download

5 minutes of typing, then 20 to 40 of waitingHim, alone

The repository ships a launcher written for macOS. Use it rather than the generic instructions:

$ cd ~/ACE-Step-1.5
$ chmod +x start_gradio_ui_macos.sh
$ ./start_gradio_ui_macos.sh

It detects the environment, checks for updates, installs anything missing, and starts the web interface. The first run also downloads the model weights, which are between 4 and 9 GB depending on which size he chooses. That download happens once.

If he would rather skip the environment checks on later days, uv run acestep starts the same interface directly. Both open http://localhost:7860 in the browser.

Checkpoint

The page loads at http://localhost:7860 and shows a lyrics box and a tags or style box. Leave the Terminal window open: closing it stops the app.

4

Turn the morning's email into a track

5 minutes a songHim, alone

Two fields, straight from the Grok reply. The ===ESTILO=== block goes into the tags or style field, and the ===LETRA=== block goes into the lyrics field.

The [verse] and [chorus] tags stay in English even though the words are Spanish. That is what the model reads to build the song's shape, and it is the most common thing to lose in a copy and paste. If the structure comes out wrong, check those tags first.

Set the duration to match DURACIÓN OBJETIVO from the prompt. Three and a half minutes is 210 seconds. On an M2 Max a track that length renders in about a minute and a half.

On 16 GB, use the smaller 2B model. The 4B is better and wants the memory to match. He can change this later without reinstalling anything, so start small and hear the difference before deciding.

Save the result as cancion.wav in ~/gospel-song/.

Checkpoint

cancion.wav plays, a voice is singing his Spanish lyrics, and the length is roughly what he asked for. The voice will not be his yet. That is the next half.

Part two: Applio, the voice

5

Install Python 3.10 alongside the one he has

5 minutesScreen share

Session 1 of the Mac guide installed Python 3.12, which is what everything else in this build uses. Applio wants 3.10. Homebrew keeps versions side by side, so this adds one without disturbing the other. 

$ brew install python@3.10
Checkpoint

Both of these answer, with different numbers:

$ python3.10 --version
Python 3.10.x
$ python3 --version
Python 3.12.x
6

Clone Applio and run its installer

10 minutes, plus a long downloadScreen share 
$ cd ~
$ git clone https://github.com/IAHispano/Applio.git
$ cd Applio
$ chmod +x run-install.sh run-applio.sh
$ ./run-install.sh

The installer builds its own virtual environment inside ~/Applio and pulls the RVC dependencies into it. This is the largest download in the build after the ACE-Step weights.

Applio's documentation is written by a Spanish-speaking team, so when something needs looking up he can read it in his own language. That is a real advantage over the original RVC project.

Checkpoint

run-install.sh ends without an error, and ls -a ~/Applio shows a .venv folder. If it stopped partway, run it again: it picks up rather than starting over.

7

Launch it and load his voice

10 minutesScreen share 
$ cd ~/Applio && ./run-applio.sh

A browser tab opens at http://localhost:6969. Note that this is a different port from ACE-Step, which matters in a moment.

Go to the Inference tab. Put the .pth and .index pair from the Colab training run into ~/Applio/logs/ in a folder named after the model, then use the refresh control so the dropdown picks them up. Select the model, then select its index file underneath.

Checkpoint

His model name appears in the voice dropdown on the Inference tab, and selecting it does not throw an error in the Terminal window.

Part three: the chain, every morning

8

Four steps from lyrics to a finished vocal

about 10 minutes a songHim, alone

Both apps can run at the same time, ACE-Step on 7860 and Applio on 6969, in two Terminal windows. That is how a normal morning goes: generate in one tab, convert in the other.

One. ACE-Step writes the track. Save it as cancion.wav.

Two. Demucs pulls the vocal away from everything else:

$ cd ~/gospel-song
$ demucs --two-stems=vocals cancion.wav
# -> separated/htdemucs/cancion/{vocals.wav, no_vocals.wav}

Three. In Applio's Inference tab, feed it separated/htdemucs/cancion/vocals.wav and save the output as vocals_clonada.wav. This is the step that takes seconds, not minutes.

Four. ffmpeg puts his vocal back over the untouched instrumental:

$ ffmpeg -i separated/htdemucs/cancion/no_vocals.wav -i vocals_clonada.wav \
    -filter_complex "[1:a]volume=1.15[v];[0:a][v]amix=inputs=2:duration=longest" \
    -c:a pcm_s16le final.wav

The volume=1.15 lifts the vocal slightly above the backing. It is the one number worth adjusting by ear on the first few songs, and once it sounds right it stays right.

Checkpoint

final.wav is the whole song, the voice is recognisably his, and the instrumental is undamaged. This is the file the video step in the pipeline plan expects.

9

The API, for when the script exists

Not yetReference only

run_dia.py, from prompt 2 on the Prompts page, cannot click buttons in a web interface. ACE-Step ships a REST server for exactly that reason: 

$ uv run acestep-api
# http://localhost:8001

He does not need this until he has made a couple of weeks of videos by hand and is ready to automate. It is here so that when the coding AI asks what it should call, the answer is already written down.

When something sounds wrong

Almost every bad result traces back to one of these five, and they are quick to tell apart.

What he hearsWhere it comes fromWhat to change
Vocal sounds metallic or robotic Applio Lower the index rate. If it persists across every song, the dataset was speech rather than singing and needs rerecording.
Vocal is in the wrong octave Applio The transpose setting, in semitones. Twelve up or twelve down is one octave.
Song has no chorus, or repeats oddly ACE-Step The [verse] and [chorus] tags did not survive the paste. Check the lyrics box, not the model.
Backing instruments bleed into the converted vocal Demucs Separation was imperfect before Applio ever saw it. Try UVR with a different model for that song.
Track is much shorter or longer than asked ACE-Step The duration control, not the lyrics. Set it in seconds and regenerate.
